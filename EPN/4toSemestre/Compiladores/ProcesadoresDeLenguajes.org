* Procesador de lenguaje 
Básicamente ingresa un lenguaje o programa y realiza una operación sobre ellas. Existiendo 5 tipos de procesadores de lenguaje:
** Traductor
Entra un algo y lo cambia algo equivalente. Mantiene el significado relevante de la entrada, solo cambia su representación. Por ejemplo el traductor de Google cambia de un idioma a otro sin cambiar su significado.
** Compilador
Es una especie de traductor, cambia el programa fuente a un código objeto para ser ejecutado: [[id:24e413ed-bbb6-4759-af51-bb0caa52daf6][Conceptos generales
]]es el más rápido para ser ejecutado.
** Ensamblador
Otro tipo de traductor, pero lo que traduce es lenguaje ensamblador, y lo pasa al lenguaje de máquina, 1's y 0's. Las instrucciones ensamblador corresponden a las ISA's (instruccion set arquitecture) es decir vienen dichas por el set de instrucciones del procesador.
** Intérprete
También traduce las instrucciones del código fuente, pero lo hace linea por linea y encima las ejecuta linea por linea también, el problema es que los intérpretes antiguos cuando existía un error tenia que volver a interpretar desde la linea 1 otra vez. Esto se solucionó con los interpretes incrementales que no tienen que interpretar todo de nuevo. Ejemplo python.
** Simulador
Lo que hace es imitar el comportamiento de otra máquina a través de software, mantiene variables de la maquina simulada y repite el  [[id:35bd9582-7cfd-4816-b9be-55ab10aa60a1][Circulo básico del CPU]].

Pese a que no se debería clasificar la tecnología con una sola etiqueta, muchas veces se puede elegir una sobre otra dependiendo el objetivo.
- Si se necesita tener un desempeño nativo es mejor usar la compilación.
- Si se necesita tener interacción inmediata con el programa es mejor usar un interprete.
- Si se esta usando lenguaje de bajo nivel es mejor usar un ensamblador.
- Y por ultimo si se necesita probar otra arquitectura es mejor usar un simulador.

** Loader
:PROPERTIES:
:ID:       61090462-b2e8-4b7f-9ad3-bb98dfc27dbc
:END:
Es quien carga el ejecutable producido por el linker en la memoria del procesador y alli se empieza a ejecutar el programa.

Lo que hace es:
1. Leer el encabezado para saber el formato, el tamaño etc.
2. Luego crea el espacio de memoria donde coloca el código, los datos y reserva la pila y el heap. La pila es la memoria que se usa para las llamadas a funciones donde la ultima llamada que entra es la que sale primero. Por otro lado el heap se usa para la memoria dinámica, como una bodega para guardar los datos cuando no sabemos cuanta memoria va a ocupar.
3. Si es dinámico el enlace, se cargan las bibliotecas y se resuelven las dependencias
4. Ajustar direcciones si es necesario: Se pone al programa en una dirección por seguridad)
5. Pone el contador de programa en el punto de entrada, alli el CPU empieza el fetch y sigue con  [[id:35bd9582-7cfd-4816-b9be-55ab10aa60a1][Circulo básico del CPU]]

* Definiciones
** Transliterador
El transliterador básicamente cambia de un símbolo a otro símbolo, por ejemplo cambiar los números romanos a numero decimales. La cosa es que cada símbolo cambia según una tabla, no cambia el significado ni analiza nada solo cambia los símbolos.
** Parser
El programa recibe una secuencia de tokens y decide si forma una estructura permitida por una gramática. Si es correcta se acepta y se hace un árbol con esa estructura, básicamente forma parte de un analizador sintáctico [[id:24e413ed-bbb6-4759-af51-bb0caa52daf6][Conceptos generales]].
